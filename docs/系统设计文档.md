## 1. 系统概述

### 1.1 项目背景

本系统是一套面向火锅餐饮行业的**全流程数字化管理解决方案**，涵盖用户端小程序和管理端后台，旨在通过技术创新提升用户体验、优化运营效率、增强客户粘性。

### 1.2 系统定位

- **用户端**: 微信小程序，提供预约、点餐、评价、积分等核心功能
- **管理端**: Web管理后台，提供数据管理、统计分析、运营配置等功能
- **后端服务**: Laravel RESTful API，提供统一的数据接口和业务逻辑

### 1.3 核心价值

- **用户体验提升**: 可视化桌位选择、实时排队信息、便捷的预约和评价流程
- **运营效率优化**: 自动化业务流程、智能数据分析、异常监控预警
- **客户关系管理**: 积分会员体系、精准营销、评价追踪优化
- **数据驱动决策**: 多维度统计分析、异常检测、运营报表

### 1.4 技术栈

**后端技术栈**:
- **框架**: Laravel 10.10+
- **PHP版本**: PHP 8.2+
- **数据库**: MySQL 8.0+ / MariaDB 10.6+
- **认证**: Laravel Sanctum 3.2+
- **HTTP客户端**: Guzzle 7.2+

**前端技术栈**:
- **框架**: Vue 3.3+ (Composition API)
- **语言**: TypeScript 5.3+
- **UI组件库**: Element Plus 2.4+
- **状态管理**: Pinia 2.1+
- **路由**: Vue Router 4.2+
- **图表**: ECharts 6.0+
- **构建工具**: Vite 5.0+

**开发工具**:
- **代码规范**: Laravel Pint
- **测试框架**: PHPUnit 10.1+
- **Mock框架**: Mockery 1.4+

## 2. 技术架构

### 2.1 整体架构

```
┌─────────────────┐         ┌─────────────────┐
│  微信小程序前端  │         │  Web管理后台    │
│  (WeChat Mini)  │         │  (Vue 3 + TS)   │
└────────┬────────┘         └────────┬────────┘
         │                            │
         │  HTTPS / RESTful API       │
         │                            │
         └────────────┬───────────────┘
                      │
         ┌────────────▼───────────────┐
         │   Laravel API Server      │
         │   (Laravel 10 + Sanctum)  │
         └────────────┬───────────────┘
                      │
         ┌────────────┴───────────────┐
         │                            │
    ┌────▼────┐                 ┌────▼────┐
    │  MySQL  │                 │  Redis  │
    │ 8.0+    │                 │ (Cache) │
    └─────────┘                 └─────────┘
```

### 2.2 架构特点

#### 2.2.1 前后端分离

- **后端**: 提供RESTful API，统一数据接口
- **前端**: 独立部署，通过API与后端通信
- **优势**: 前后端独立开发、部署和维护

#### 2.2.2 事件驱动架构

- **Observer模式**: 订单、评价、用户等模型使用Observer自动触发业务逻辑
- **事件解耦**: 业务逻辑解耦，易于扩展和维护
- **自动化流程**: 积分发放、状态更新等自动化处理

#### 2.2.3 服务化设计

**核心服务层**:
- `ReservationService`: 预约业务逻辑
- `ReviewService`: 评价业务逻辑
- `PointService`: 积分业务逻辑
- `QueueService`: 排队业务逻辑
- `OrderService`: 订单业务逻辑
- `DepositService`: 定金业务逻辑
- `TaskService`: 任务业务逻辑
- `AchievementService`: 成就业务逻辑
- `CheckinService`: 签到业务逻辑
- `LotteryService`: 抽奖业务逻辑
- `ShareService`: 分享业务逻辑
- `InvitationService`: 邀请业务逻辑
- `PointRuleService`: 积分规则管理
- `PointExpirationService`: 积分过期管理
- `PointStatisticsService`: 积分统计分析
- `PointAnomalyDetectionService`: 积分异常检测
- `ProfanityFilterService`: 不文明语言过滤
- `AuditLogService`: 审计日志服务

### 2.3 数据一致性保证

#### 2.3.1 事务机制

- **关键操作**: 预约创建、积分变动、订单支付等使用数据库事务
- **原子性保证**: 保证数据一致性，防止部分成功的情况

#### 2.3.2 幂等性保证

- **预约创建**: 使用`idempotency_key`防止重复提交
- **积分兑换**: 使用`idempotency_key`防止重复兑换
- **评价提交**: 基于业务唯一性（user_id + order_id + dish_id）

#### 2.3.3 并发控制

- **数据库锁**: 使用`lockForUpdate()`防止并发冲突
- **分布式锁**: Redis分布式锁用于跨服务操作
- **乐观锁**: version字段用于高并发读多写少场景

### 2.4 性能优化策略

#### 2.4.1 缓存策略

- **积分规则缓存**: 使用Redis缓存积分规则配置
- **可用桌位列表缓存**: 缓存可用桌位列表，减少数据库查询
- **频率限制缓存**: 使用Cache实现频率限制

#### 2.4.2 数据库优化

- **索引优化**: 对常用查询字段建立索引
- **查询优化**: 避免N+1查询问题，使用预加载
- **分页查询**: 大数据量使用分页查询

#### 2.4.3 前端优化

- **组件懒加载**: 路由级别的代码分割
- **图片懒加载**: 图片按需加载
- **虚拟滚动**: 大数据量列表使用虚拟滚动

## 3. 功能模块详解

### 3.1 用户认证模块

#### 3.1.1 微信登录

- **接口**: `POST /api/v1/auth/wechat-login`
- **功能**: 微信小程序用户登录，获取用户openid，创建或更新用户信息
- **返回**: JWT Token，用于后续API调用

#### 3.1.2 用户信息

- **接口**: `GET /api/v1/users/me`
- **功能**: 获取当前登录用户信息
- **返回**: 用户基本信息、积分信息、会员等级等

### 3.2 预约管理模块

#### 3.2.1 核心功能

**1. 可视化桌位选择**
- 地图式布局展示
- 实时状态显示（available/reserved/occupied/maintenance）
- 智能推荐（根据用餐人数筛选）

**2. 时间段预约**
- 选择具体日期和时间段
- 自动检查时间冲突
- 支持特殊需求备注

**3. 预约定金机制**
- 在线支付定金（微信支付）
- 定金金额配置化（默认50元）
- 定金可在订单结算时抵扣
- 15分钟确认机制

**4. 预约状态管理**
- `pending`: 待确认（15分钟内需确认）
- `confirmed`: 已确认
- `cancelled`: 已取消
- `completed`: 已完成
- `expired`: 已过期

#### 3.2.2 主要接口

- `GET /api/v1/reservations/tables`: 获取可用桌位列表
- `POST /api/v1/reservations`: 创建预约
- `PUT /api/v1/reservations/{id}/confirm`: 确认预约
- `PUT /api/v1/reservations/{id}/cancel`: 取消预约
- `POST /api/v1/reservations/{id}/pay-deposit`: 支付定金
- `POST /api/v1/reservations/{id}/arrive`: 到店确认

#### 3.2.3 管理端功能

- 预约列表查询（支持筛选和搜索）
- 预约详情查看
- 预约确认/取消
- 批量标记为已查看
- 批量删除
- 未查看数量统计

### 3.3 评价管理模块

#### 3.3.1 核心功能

**1. 多维度评价**
- 1-5星评分
- 文字评价（最多500字）
- 图片上传（最多3张）
- 标签系统
- 菜品关联

**2. 自动审核机制**
- 不文明语言过滤（中英文敏感词库）
- 频率限制（1小时内最多5条）
- 自动通过审核

**3. 评价追踪优化机制**（核心创新功能）
- 管理员可采纳评价建议
- 追踪优化状态（pending/in_progress/completed/cancelled）
- 记录优化进展
- 用户可查看优化状态

**4. 管理员互动**
- 回复评价
- 审核评价
- 采纳建议
- 更新追踪状态

#### 3.3.2 主要接口

- `POST /api/v1/reviews`: 提交评价
- `GET /api/v1/dishes/{dishId}/reviews`: 获取菜品评价列表
- `GET /api/v1/reviews`: 获取用户评价列表
- `GET /api/v1/reviews/tracking`: 获取追踪优化的评价

#### 3.3.3 管理端功能

- 评价列表查询（支持筛选和搜索）
- 评价详情查看
- 评价审核（通过/拒绝）
- 回复评价
- 采纳评价建议
- 更新追踪状态
- 批量标记为已查看
- 批量删除
- 未查看数量统计

### 3.4 订单管理模块

#### 3.4.1 核心功能

**1. 订单创建**
- 关联桌位（可选）
- 关联预约（可选）
- 添加订单项（菜品）
- 计算订单金额

**2. 支付集成**
- 微信支付
- 支持多种支付方式（可扩展）

**3. 优惠抵扣**
- 预约定金抵扣
- 积分抵扣（可配置比例和上限）
- 优惠券使用
- 会员等级折扣

**4. 订单状态管理**
- `pending`: 待支付
- `paid`: 已支付
- `pending_review`: 待评价
- `completed`: 已完成
- `cancelled`: 已取消

#### 3.4.2 主要接口

- `POST /api/v1/orders`: 创建订单
- `GET /api/v1/orders`: 获取订单列表
- `GET /api/v1/orders/{id}`: 获取订单详情
- `POST /api/v1/orders/{id}/pay`: 支付订单
- `PUT /api/v1/orders/{id}`: 更新订单
- `POST /api/v1/orders/{id}/cancel`: 取消订单
- `POST /api/v1/orders/{id}/skip-review`: 跳过评价

#### 3.4.3 管理端功能

- 订单列表查询（支持筛选和搜索）
- 订单详情查看
- 订单状态更新
- 订单取消/完成
- 批量标记为已查看
- 批量删除
- 未查看数量统计

### 3.5 积分会员系统

#### 3.5.1 核心功能

**1. 多来源积分获得**
- **订单支付积分**: 订单金额 × 基础比例 × 会员等级倍数
- **评价奖励积分**: 基础积分 + 图片奖励 + 首次评价奖励
- **评价采纳奖励**: 评价被采纳获得额外积分
- **任务完成奖励**: 完成任务获得积分
- **签到奖励**: 每日签到获得积分
- **邀请奖励**: 邀请好友注册获得积分

**2. 会员等级系统**
- **等级划分**: 青铜、白银、黄金、白金等（可配置）
- **等级权益**: 不同等级享受不同的积分获得倍数
- **自动升级**: 积分达到阈值自动升级

**3. 积分状态管理**
- **总积分**: 用户累计获得的所有积分
- **可用积分**: 当前可使用的积分
- **冻结积分**: 兑换优惠券时冻结的积分

**4. 积分兑换系统**
- 兑换优惠券
- 幂等性保证（idempotency_key）
- 积分冻结机制

**5. 积分过期管理**
- 积分获得后365天过期（可配置）
- 定时任务自动处理过期积分
- 按获得时间先后顺序过期（FIFO）

**6. 积分统计与分析**
- 日报统计
- 排行榜
- 来源统计
- 异常检测

#### 3.5.2 主要接口

- `GET /api/v1/points`: 获取积分信息
- `GET /api/v1/points/levels`: 获取所有启用的段位列表
- `GET /api/v1/points/transactions`: 获取积分交易流水
- `GET /api/v1/points/expiring`: 获取即将过期的积分
- `POST /api/v1/points/redeem`: 积分兑换

#### 3.5.3 管理端功能

- 积分查询（用户积分详情、交易流水）
- 积分调整（手动调整用户积分）
- 积分规则配置
- 积分段位管理
- 积分统计（日报、排行榜、来源统计）
- 积分异常检测

## 6. 业务流程设计

### 6.1 预约流程

```
用户选择日期和时间段
    ↓
系统返回可用桌位列表（可视化展示）
    ↓
用户选择桌位，填写联系人信息
    ↓
提交预约请求（携带idempotency_key）
    ↓
系统检查：
  - 桌位是否可用（数据库锁）
  - 时间段是否冲突
  - 幂等性检查
    ↓
创建预约记录（status: pending）
占用桌位资源（status: reserved）
    ↓
15分钟内用户确认预约
    ↓
预约状态变为confirmed
    ↓
用户到店用餐
    ↓
预约状态变为completed
```

### 6.2 评价流程

```
用户完成订单，订单状态变为pending_review
    ↓
用户进入订单详情页，点击"评价"
    ↓
选择菜品，填写评分、内容、上传图片、选择标签
    ↓
提交评价请求
    ↓
系统检查：
  - 订单是否存在且处于pending_review状态
  - 是否已评价过该菜品
  - 频率限制检查（1小时最多5条）
    ↓
不文明语言过滤
    ↓
创建评价记录（status: approved，自动通过）
    ↓
自动发放评价积分奖励
    ↓
更新菜品评分统计
    ↓
检查订单是否所有菜品都已评价
    ↓
是 → 订单状态自动变为completed
否 → 订单保持pending_review状态
```

### 6.3 积分获得流程

```
订单支付 / 评价提交 / 任务完成 / 签到 / 邀请
    ↓
相应Observer触发
    ↓
检查是否已发放过积分
    ↓
否 → 计算应得积分
    ↓
增加用户总积分和可用积分
    ↓
检查并更新会员等级
    ↓
记录积分交易流水
    ↓
安排积分过期时间（365天后）
```

### 6.4 积分兑换流程

```
用户查看可用优惠券列表
    ↓
选择优惠券，点击"兑换"
    ↓
系统检查：
  - 优惠券是否可用
  - 库存是否充足
  - 用户可用积分是否足够
    ↓
幂等性检查（idempotency_key）
    ↓
扣除用户可用积分
增加用户冻结积分
    ↓
减少优惠券库存
    ↓
生成用户优惠券（唯一兑换码）
    ↓
```

## 7. 安全与权限

### 7.1 认证机制

#### 7.1.1 用户端认证

- **方式**: Laravel Sanctum Token认证
- **Token生成**: 微信登录成功后生成
- **Token有效期**: 7天（可配置）
- **Token刷新**: 支持Token刷新机制

#### 7.1.2 管理端认证

- **方式**: Laravel Sanctum Token认证（admin guard）
- **Token生成**: 用户名密码登录成功后生成
- **Token有效期**: 2小时（可配置）
- **记住我**: 支持记住我功能（延长Token有效期）

### 7.2 权限控制

#### 7.2.1 基于角色的权限控制（RBAC）

- **角色管理**: 创建、编辑、删除角色
- **权限管理**: 细粒度权限控制
- **用户角色分配**: 为用户分配角色

#### 7.2.2 权限中间件

- **路由保护**: 每个管理端路由使用权限中间件保护
- **权限检查**: `permission:xxx`中间件检查用户权限
- **数据权限**: 支持数据级别的权限控制

### 7.3 数据安全

#### 7.3.1 输入验证

- **参数验证**: 使用Laravel Request验证
- **SQL注入防护**: 使用ORM，避免直接SQL查询
- **XSS防护**: 输出转义

#### 7.3.2 敏感数据处理

- **手机号**: 加密存储（可选）
- **支付数据**: JSON加密存储
- **日志脱敏**: 日志中不记录完整敏感信息

### 7.4 内容安全

#### 7.4.1 不文明语言过滤

- **服务**: `ProfanityFilterService`
- **词库**: 中英文敏感词库
- **检测范围**: 评价内容、标签

#### 7.4.2 频率限制

- **评价提交**: 1小时内最多5条
- **登录失败**: 同一IP 1小时内失败>5次锁定账户
- **API限流**: 使用Laravel Rate Limiting

## 8. 日志与监控

### 8.1 日志系统

#### 8.1.1 日志分类

系统使用模块化日志分类，每个模块包含以下日志级别：

**模块分类**:
- `order`: 订单相关日志
- `deposit`: 定金相关日志
- `user`: 用户相关日志
- `table`: 桌位相关日志
- `point`: 积分相关日志
- `reservation`: 预约相关日志
- `review`: 评价相关日志
- `payment`: 支付相关日志

**日志级别**:
- `debug`: 调试信息
- `info`: 一般信息
- `warning`: 警告信息
- `error`: 错误信息

**日志文件结构**:
```
storage/logs/
├── order/
│   ├── debug-2026-01-05.log
│   ├── info-2026-01-05.log
│   ├── warning-2026-01-05.log
│   ├── error-2026-01-05.log
│   └── order-2026-01-05.log (综合日志)
├── deposit/
│   └── ...
└── ...
```

#### 8.1.2 日志记录内容

**业务日志**:
- 预约创建、确认、取消
- 评价提交、审核
- 订单创建、支付、完成
- 积分获得、消费、过期
- 用户注册、登录

**审计日志**:
- 管理员操作（登录、权限变更、数据修改）
- 积分调整
- 评价采纳、追踪更新

#### 8.1.3 日志工具

**LoggerHelper**: 统一的日志记录工具类

```php
LoggerHelper::orderInfo('订单创建成功', ['order_id' => 123]);
LoggerHelper::depositError('定金退款失败', ['reservation_id' => 456]);
LoggerHelper::userDebug('用户信息加载', ['user_id' => 789]);
```

### 8.2 监控指标

#### 8.2.1 业务指标

- **预约成功率**: 预约创建成功数 / 预约请求总数

- **数据库查询时间**: 慢查询监控
- **缓存命中率**: Redis缓存命中率

#### 8.2.3 异常指标

- **API错误率**: 4xx、5xx错误率
- **积分异常**: 积分异常检测结果
- **系统异常**: 系统错误、异常日志

### 9.3 定时任务

#### 9.3.1 Laravel Schedule

系统使用Laravel Schedule管理定时任务：

```php
// app/Console/Kernel.php
protected function schedule(Schedule $schedule)
{
    // 检查过期预约
    $schedule->command('reservations:check-expired')->daily();
    
    // 处理积分过期
    $schedule->command('points:process-expirations')->daily();
    
    // 刷新每日任务
    $schedule->command('tasks:refresh-daily')->daily();
    
    // 刷新每周任务
    $schedule->command('tasks:refresh-weekly')->weekly();
    
    // 释放过期桌位占用
    $schedule->command('tables:release-expired')->everyMinute();
    
    // 计算积分统计
    $schedule->command('points:calculate-statistics')->daily();
}
```

#### 9.3.2 Cron配置

```bash
* * * * * cd /path-to-project && php artisan schedule:run >> /dev/null 2>&1
```
